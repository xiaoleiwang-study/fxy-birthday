# 手机生日纪念册与按钮粒子效果

## 1. 先讲业务

朋友主要用手机浏览生日网页，希望照片、故事和祝福更清晰，许愿时能看到粒子效果，点击按钮即可完成操作。

原页面有星空、照片、蛋糕和信件，但章节之间空白较长，部分照片与文字叠在一起，最后的信件没有关闭入口。本次保留原素材和正文，重新安排正常文档流布局，增加粒子蛋糕、点击散开后汇成爱心、再次播放和可关闭信件。没有增加摄像头、麦克风或数据库。

界面验证范围是本地构建、自动化测试及桌面浏览器的小屏视口检查；不代表已在真实手机或微信中测试。线上部署需单独核对 Pages 构建记录和实际响应。

## 2. 程序是怎么做到的

本质上是把一组点的三维坐标投影成屏幕上的圆点，点击后逐步改变每个点的位置。

| 顺序 | 调用关系 | 处理与输出 |
|---|---|---|
| 1 | 进入按钮 → main.js | 开场过渡独立于音频播放承诺，解除正文 inert；音乐失败仍可读故事 |
| 2 | IntersectionObserver → mountParticleCake | 蛋糕接近视口后初始化，所需观察接口不存在则返回 null，保留原蛋糕 |
| 3 | createParticles → Canvas 绘制 | 每个点保存 cake、burst、heart 三组坐标，投影后绘制 |
| 4 | 许愿按钮 → WishSequence.start → positionAt | 设置播放锁，先从蛋糕散开，再汇成爱心；播放结束显示祝福并允许回放 |
| 5 | 可见性事件 → sync | 不可见或页面转入后台时取消动画帧，恢复后继续绘制 |
| 6 | 礼物按钮 → setupLetter | 原生 dialog 优先；缺少原生 API 时使用 open 属性回退，关闭后焦点回到礼物 |

## 3. 字段与状态

| 字段 | 谁写入 | 谁读取 | 意义 |
|---|---|---|---|
| cake / burst / heart | createParticles | positionAt、draw | 同一个粒子在三个阶段的位置 |
| startedAt / running | WishSequence | start、progress | 计算进度并避免播放中重启 |
| wishing / wished | 按钮事件 | 点击处理、延迟初始化 | 阻止重复操作，并衔接先点击后初始化的情况 |
| visible / raf | 观察回调、sync | frame | 决定是否消耗动画帧资源 |
| has-particles | 渲染初始化和丢失事件 | CSS | 决定显示粒子画布还是原蛋糕 |
| open / scrollTop | setupLetter | 浏览器及 CSS | 控制信件显示，每次从开头阅读 |

### 核心取舍

**Canvas 投影：** 1050 个手机粒子或 1800 个桌面粒子，足以呈现三层蛋糕和心形；不需要模型文件和设备权限。它不是完整 3D 网格，没有真实遮挡或光照，复杂场景才需要更完整的 WebGL 实现。

**可见性与进度：** 动画根据经过的毫秒数推进，手机绘制间隔约 32 毫秒；画布离屏或页面隐藏后暂停请求动画帧。减少动态偏好开启时只绘制静态状态。帧预算是实现策略，不等同于已测得真实设备帧率。

**兼容优先：** 在分配渲染资源之前检查观察接口；Canvas 不可用时保留已有蛋糕。信件先判断 showModal 和 close 是否可用，否则使用普通显隐、Escape 及焦点控制。回退焦点循环目前只适用于信件里唯一的关闭按钮；未来加链接时需要扩展。

未采用：摄像头手势、麦克风吹气、额外数据库；它们不是本次点击体验的前提。
